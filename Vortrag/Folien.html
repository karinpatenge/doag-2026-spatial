SDO_GEOMETRY: Ein Typ sie alle zu knechten

-- Der Datentyp SDO_GEOMETRY: Eine Spalte dieses Typs nimmt jede Art von Geometrie auf
create type sdo_geometry as object (
  sdo_gtype      number,               -- Geometrietyp, z. B. 2001 = Punkt (siehe unten)
  sdo_srid       number,               -- Koordinatensystem, z. B. 25832 (→ Folie 7)
  sdo_point      sdo_point_type,       -- x, y, z: nur für einen einzelnen Punkt
  sdo_elem_info  sdo_elem_info_array,  -- Aufbau von Linien und Flächen (→ Folie 14)
  sdo_ordinates  sdo_ordinate_array);  -- alle Koordinaten von Linien und Flächen (→ Folie 14)

Der Geometrietyp SDO_GTYPE: vier Stellen

2D · Tausender
Anzahl der Dimensionen
0L · Hunderter
Dimension des Messwerts, 0 = keiner
01TT · Zehner und Einer
Art der Geometrie
  • D = 2: x, y · D = 3: x, y, z oder x, y, Messwert · D = 4: x, y, z, Messwert
  • L zählt nur beim linearen Referenzieren, etwa der Kilometrierung einer Autobahn: Jeder Punkt trägt dann einen Messwert, L sagt, in welcher Dimension er steht.

Übliche Formate

WKT (Well-Known Text) – lesbarer Text, Standard des Open Geospatial Consortium

GeoJSON – das Format der Webkarten

  • 2008 von einer Gruppe von Open-Source-Entwicklern erfunden
  • seit 2016 Standard der IETF: RFC 7946
  • immer WGS 84 (SRID 4326) → deshalb sdo_cs.transform

Kapitel 3 · Wo liegt das Elternhaus eigentlich?

Koordinatensysteme

Die SRID (Spatial Reference ID) ist die Nummer eines Koordinatensystems, meist aus dem EPSG-Register. EPSG war die European Petroleum Survey Group, ab 1986 eine Arbeitsgruppe von Geodäten aus der Ölindustrie. Seit 2005 pflegt der Verband der Öl- und Gasförderer (IOGP) das Register unter epsg.org.

Wie viele Koordinatensysteme kennt die Datenbank?

select coord_ref_sys_kind as art, count(*) as anzahl
  from mdsys.sdo_coord_ref_sys
  group by coord_ref_sys_kind
  order by anzahl desc;

Ein Haus, drei Zahlenpaare

Das Elternhaus in drei Koordinatensystemen

select s.srid,
       sdo_cs.transform(o.geo, s.srid).get_wkt() as wkt
  from ort o
  cross join (select column_value as srid
                from table(sys.odcinumberlist(25832, 4326, 3857))) s
  where o.name = 'Elternhaus';

Die drei Bezugssysteme

SRID 25832: ETRS89 / UTM Zone 32N – Meter
ETRS89 (European Terrestrial Reference System 1989) ist an die eurasische Kontinentalplatte gebunden: Punkte in Europa behalten ihre Koordinaten. Zu WGS 84 sind es inzwischen knapp 1 m Unterschied.
UTM (Universal Transverse Mercator) teilt die Erde in 60 Zonen zu je 6° Länge und bildet jede Zone für sich auf die Ebene ab. Deutschland liegt in den Zonen 32 und 33.
SRID 4326: WGS 84 – Grad
WGS 84 (World Geodetic System 1984) ist das weltweite Bezugssystem des US-Verteidigungsministeriums, die Grundlage von GPS und GeoJSON.
SRID 3857: Web-Mercator – „Meter“
Die Mercator-Projektion auf einer Kugel, 2005 mit Google Maps eingeführt und heute die Projektion fast aller Webkarten. Gut zum Anzeigen, schlecht zum Messen.
Ein Breitengrad ist überall etwa 111 km lang, ein Längengrad bei Nürnberg nur 72,4 km.
Länge und Breite vertauscht: Aus 11,20° O · 49,46° N wird 49,46° O · 11,20° N – das Elternhaus steht bei Bosaso in Somalia.

Dieselbe Welt, vier Projektionen

Länder und Kreise mit 500 km Radius (sdo_buffer), live umgerechnet mit sdo_cs.transform(geo, :srid)

Wie groß ist ein Kreis mit 500 km Radius?

with projektion as (select c.srid,
                           c.cs_name as name
                      from mdsys.cs_srs c
                     where c.srid in (3857, 212992, 1009801)),
     kreis as (select column_value as breite,
                      sdo_geom.sdo_buffer(sdo_geometry(2001, 4326, sdo_point_type(11, column_value, null), null, null),
                                          500000, pa_geo.toleranz(), 'unit=M arc_tolerance=1000') as geo
                 from table(sys.odcinumberlist(0, 49, 70)))
select p.srid,
       p.name,
       k.breite,
       round(sdo_geom.sdo_area(k.geo, pa_geo.toleranz(), 'unit=SQ_KM')) as echte_qkm,
       round(sdo_geom.sdo_area(sdo_cs.transform(k.geo, p.srid), pa_geo.toleranz()) / 1e6) as karten_qkm,
       round(100 * (sdo_geom.sdo_area(sdo_cs.transform(k.geo, p.srid), pa_geo.toleranz()) / 1e6
                    / sdo_geom.sdo_area(k.geo, pa_geo.toleranz(), 'unit=SQ_KM') - 1), 1) as abweichung_prozent
  from projektion p
  cross join kreis k
  order by p.srid, k.breite;

Die Toleranz

Liegen zwei Punkte weniger als 5 cm auseinander, sind sie derselbe Punkt.

Fast jede Funktion von Oracle Spatial verlangt diesen Wert. Wir legen ihn an genau einer Stelle ab.

Reines SQL kann keine Package-Konstanten lesen (ORA-06553) – deshalb die Funktion.

create or replace package pa_geo is
  -- Toleranz in Metern für alle Spatial-Funktionen
  cToleranz constant number := 0.05;

  function toleranz return number deterministic;
end;
/
create or replace package body pa_geo is

  ----------------------------------------------------------------------------------------------------------------------
  function toleranz return number deterministic is
  begin
    return cToleranz;
  end;

end;
/

Wie tief im Wald liegt die Feuerstelle?

select sdo_geom.sdo_distance(sdo_geometry(2001, null, sdo_cs.transform(h.geo, 4326).sdo_point, null, null),
                             sdo_geometry(2001, null, sdo_cs.transform(f.geo, 4326).sdo_point, null, null),
                             pa_geo.toleranz()) as ohne_srid_grad,
       sdo_geom.sdo_distance(sdo_cs.transform(h.geo, 4326), sdo_cs.transform(f.geo, 4326),
                             pa_geo.toleranz(), 'unit=M') as wgs84_m,
       sdo_geom.sdo_distance(sdo_cs.transform(h.geo, 3857), sdo_cs.transform(f.geo, 3857),
                             pa_geo.toleranz()) as web_mercator_m,
       sdo_geom.sdo_distance(h.geo, f.geo, pa_geo.toleranz()) as utm_32n_m
  from ort h
  cross join ort f
  where h.name = 'Elternhaus'
    and f.name = 'Feuerstelle';

Ergebnis

Signatur von sdo_geom.sdo_distance

function sdo_distance(geom1       in sdo_geometry,
                      geom2       in sdo_geometry,
                      tol         in number   default null,
                      unit        in varchar2 default null,
                      ellipsoidal in varchar2 default null)
  return number;
  • unit: Einheit des Ergebnisses, etwa 'unit=M' oder 'unit=KM'
  • ellipsoidal: 'TRUE' rechnet auf dem Ellipsoid statt auf der Kugel
Kein SRID: Der Abstand ist 0. Die Toleranz gilt in den Einheiten der Koordinaten, hier also 0,05 Grad. Das sind bei Nürnberg 3,6 bis 5,6 km – Elternhaus und Feuerstelle gelten als derselbe Punkt.

Kapitel 5 · Heimweg und Irrweg

Im Mondschein folgen Hänsel und Gretel den weißen Kieselsteinen, Stein für Stein, bis nach Hause.

Hänsel: „Eigentlich wollte ich keine einzelnen Punkte, sondern einen Weg.“

Wie eine Linie gespeichert wird

Eine Linie aus drei Punkten

sdo_geometry(2002,                                   -- sdo_gtype: 2002 = Linie aus x, y
             null,                                   -- sdo_srid
             null,                                   -- sdo_point
             sdo_elem_info_array(1, 2, 1),           -- sdo_elem_info
             sdo_ordinate_array(1, 1, 4, 3, 7, 2))   -- sdo_ordinates
sdo_elem_info: je Teil ein Dreierpaket
1Der Teil beginnt an Stelle 1 der Koordinatenliste.
2Art: Linie
1Interpretation: gerade Abschnitte

sdo_ordinates: alle Koordinaten hintereinander, x, y, x, y, …

Aus Kieselsteinen wird der Heimweg

Summation der einzelnen Abschnitte

with heimweg as (
  select sdo_geometry('LINESTRING (' || listagg(s.geo.sdo_point.x || ' ' || s.geo.sdo_point.y, ', ')
                                          within group (order by s.nummer) || ')', 25832) as geo
    from ort s
    where s.name = 'Kieselstein')
select round(sdo_geom.sdo_length(w.geo, pa_geo.toleranz())) as weg_meter
  from heimweg w;

Luftlinie vom ersten zum letzten Stein

select round(sdo_geom.sdo_distance(a.geo, b.geo, pa_geo.toleranz())) as luftlinie_meter
  from ort a
  cross join ort b
  where a.name = 'Kieselstein'
    and a.nummer = 1
    and b.name = 'Kieselstein'
    and b.nummer = 25;

Der Heimweg

Komma statt Punkt: Wer WKT aus Zahlen mit Nachkommastellen zusammensetzt, bekommt in einer deutschen Sitzung „11,17“ statt „11.17“. Unsere Koordinaten sind ganze Meter – sonst to_char(x, 'TM', 'nls_numeric_characters=.,').

Kapitel 6 · Das Lebkuchenhaus auf der Lichtung

Ein schneeweißes Vöglein führt die Kinder zu einem Häuschen aus Brot, mit Kuchen gedeckt. „Knusper, knusper, Knäuschen, wer knuspert an meinem Häuschen?“

Hänsel: „Steht das Häuschen noch im Wald oder auf der Lichtung?“

Gretel: „Dazu müssen wir erst wissen, wie ein Wald mit Lichtung aussieht.“

Der Wald

sdo_geometry(2003,                                             -- 2003 = Polygon aus x, y
             25832,                                            -- ETRS89 / UTM Zone 32N
             null,                                             -- nur für einzelne Punkte
             sdo_elem_info_array(1, 1003, 1),                  -- äußerer Ring, gerade Kanten
             sdo_ordinate_array(x1, y1, x2, y2, ..., x1, y1))  -- die Eckpunkte des Rings
  • 1003: äußerer Ring. Sein Rand umschließt die Fläche; innere Ringe (2003) schneiden Löcher hinein, dazu mehr beim See.
  • Interpretation 1: Die Eckpunkte sind durch gerade Kanten verbunden. 2 stünde für Kreisbögen, 3 für ein Rechteck aus zwei Ecken.
  • Der Ring ist geschlossen: Der letzte Punkt wiederholt den ersten.
  • Er läuft gegen den Uhrzeigersinn, so erkennt Oracle den äußeren Ring. Die Pfeile auf der Karte zeigen die Richtung.

Flächen mit Löchern

Der Wald mit See und Lichtung

sdo_geometry(2003,                                 -- 2003 = Polygon aus x, y
             25832,                                -- ETRS89 / UTM Zone 32N
             null,                                 -- nur für einzelne Punkte
             sdo_elem_info_array(1, 1003, 1,       -- ab Stelle 1: äußerer Ring, der Waldrand
                                 35, 2003, 1,      -- ab Stelle 35: innerer Ring, Loch für den See
                                 53, 2003, 1),     -- ab Stelle 53: innerer Ring, Loch für die Lichtung
             sdo_ordinate_array(x, y, ..., x, y,   -- Stelle 1 bis 34: der Waldrand
                                x, y, ..., x, y,   -- Stelle 35 bis 52: das Loch für den See
                                x, y, ..., x, y))  -- Stelle 53 bis 68: das Loch für die Lichtung
  • Der Wald ist eine Fläche mit zwei Löchern: Die inneren Ringe (2003) schneiden See und Lichtung heraus. Sie laufen im Uhrzeigersinn, der Waldrand gegen den Uhrzeigersinn.

Der See als eigene Fläche

sdo_geometry(2003,
             25832,
             null,
             sdo_elem_info_array(1, 1003, 1),      -- einziger Ring: das Ufer
             sdo_ordinate_array(x, y, ..., x, y))  -- wie das Loch, umgekehrt

Die Lichtung als eigene Fläche

sdo_geometry(2003,
             25832,
             null,
             sdo_elem_info_array(1, 1003, 1),      -- einziger Ring: der Rand
             sdo_ordinate_array(x, y, ..., x, y))  -- wie das Loch, umgekehrt

Ist die Fläche gültig?

select 'Wald' as beispiel,
       sdo_geom.validate_geometry_with_context(f.geo, pa_geo.toleranz()) as ergebnis
  from flaeche f
  where f.name = 'Wald'
union all
select 'Acht',
       sdo_geom.validate_geometry_with_context(
         sdo_geometry(2003, null, null, sdo_elem_info_array(1, 1003, 1),
                      sdo_ordinate_array(0, 0, 4, 4, 4, 0, 0, 4, 0, 0)), pa_geo.toleranz())
union all
select 'Falsch gedreht',
       sdo_geom.validate_geometry_with_context(
         sdo_geometry(2003, null, null, sdo_elem_info_array(1, 1003, 1),
                      sdo_ordinate_array(6, 0, 6, 4, 10, 4, 10, 0, 6, 0)), pa_geo.toleranz());
Ungültige Flächen: Die Acht bekommt ORA-13349, weil ihr Rand sich selbst kreuzt. Das falsch gedrehte Quadrat bekommt ORA-13367, weil sein äußerer Ring im Uhrzeigersinn statt gegen den Uhrzeigersinn läuft.
Jede Form sollte beim Speichern validiert werden! Traue keinem Fremdsystem, nicht mal deinem eigenen!

Reparieren mit rectify_geometry

select b.name,
       b.geo.sdo_gtype as gtype_vorher,
       sdo_util.rectify_geometry(b.geo, pa_geo.toleranz()).sdo_gtype as gtype_nachher,
       sdo_util.rectify_geometry(b.geo, pa_geo.toleranz()).get_wkt() as wkt
  from (select 'Acht' as name,
               sdo_geometry(2003, null, null, sdo_elem_info_array(1, 1003, 1),
                            sdo_ordinate_array(0, 0, 4, 4, 4, 0, 0, 4, 0, 0)) as geo
        union all
        select 'Falsch gedreht',
               sdo_geometry(2003, null, null, sdo_elem_info_array(1, 1003, 1),
                            sdo_ordinate_array(6, 0, 6, 4, 10, 4, 10, 0, 6, 0))) b;
  • sdo_util.rectify_geometry repariert, was sich eindeutig reparieren lässt: doppelte Punkte, falsche Laufrichtung und Ränder, die sich selbst kreuzen.
  • Die Acht wird an ihrem Kreuzungspunkt in zwei Dreiecke geteilt: Aus dem Polygon (2003) wird ein Multipolygon (2007).
  • Beim falsch gedrehten Quadrat kehrt die Funktion die Reihenfolge der Punkte um; der Typ bleibt 2003.
  • Danach sind beide Flächen gültig: validate_geometry_with_context liefert TRUE.
Kapitel 7 · Liegt das Hexenhaus im Wald?

Quiz: Liegt das Hexenhaus im Wald? Hand hoch für Ja!

Gretel: „Die Lichtung ist ein Loch – und ein Loch gehört nicht zum Wald.“

Wie liegen die Dinge zueinander?

select o.name,
       sdo_geom.relate(o.geo, 'determine', f.geo, pa_geo.toleranz()) as beziehung,
       sdo_geom.relate(o.geo, 'anyinteract', f.geo, pa_geo.toleranz()) as anyinteract,
       f.name as flaeche
  from ort o
  cross join flaeche f
  where o.name in ('Elternhaus', 'Hexenhaus')
    and f.name in ('Wald', 'Lichtung');

Wie groß ist der Wald, und wo ist seine Mitte?

select round(sdo_geom.sdo_area(f.geo, pa_geo.toleranz(), 'unit=HECTARE')) as hektar,
       sdo_geom.relate(sdo_geom.sdo_centroid(f.geo, pa_geo.toleranz()), 'determine',
                       f.geo, pa_geo.toleranz()) as zentroid,
       sdo_geom.relate(sdo_util.interior_point(f.geo, pa_geo.toleranz()), 'determine',
                       f.geo, pa_geo.toleranz()) as innenpunkt
  from flaeche f
  where f.name = 'Wald';
  • sdo_area rechnet in der Einheit, die unit= vorgibt, etwa SQ_M, SQ_KM, HECTARE, ACRE oder SQ_MILE. Die Datenbank kennt 25 Flächeneinheiten (mdsys.sdo_area_units) und 85 Längeneinheiten für Abstände und Längen (mdsys.sdo_dist_units, etwa M, KM, MILE, NAUT_MILE). Ohne unit= gilt die Einheit des Koordinatensystems, bei 25832 also Quadratmeter.
  • Die Fläche zählt die Löcher nicht mit: See und Lichtung sind schon abgezogen.
  • sdo_centroid liefert den Schwerpunkt der Fläche. Er kann außerhalb liegen: Hier liegt er im See, also nicht im Wald.
  • sdo_util.interior_point liefert einen Punkt, der sicher in der Fläche liegt, etwa für Beschriftungen oder Stecknadeln auf der Karte.
Kapitel 8 · Witterung und Knöchlein

„Die Hexen haben rote Augen und können nicht weit sehen, aber sie haben eine feine Witterung.“

Hexe: „Ich rieche Kinder! Wer ist im Umkreis von 300 Metern?“

Die Hexe hat eine feine Witterung

select o.name,
       round(sdo_geom.sdo_distance(o.geo, h.geo, pa_geo.toleranz())) as meter
  from ort o
  cross join ort h
  where h.name = 'Hexenhaus'
    and o.name <> 'Hexenhaus'
    and sdo_within_distance(o.geo, h.geo, 'distance=300') = 'TRUE'
  order by meter;

Operatoren stehen im where und fragen zuerst den Spatial Index:

  • Funktionen wie sdo_geom.sdo_distance rechnen für jede Zeile die genaue Geometrie durch. Bei vielen Zeilen dauert das.
  • Operatoren arbeiten in zwei Stufen: Erst liefert der Index alle Kandidaten, deren umschließendes Rechteck passt (Primärfilter). Nur für diese rechnet die Datenbank genau nach (Sekundärfilter).
  • Sie liefern den Text 'TRUE' und stehen deshalb mit = 'TRUE' im where.
  • sdo_within_distance – Wer ist im Umkreis? Der Abstand steht als Text im dritten Parameter, hier 'distance=300' in Metern.
  • sdo_nn – Wer ist am nächsten? Braucht einen Index.
  • sdo_relate, sdo_inside, sdo_anyinteract – Wo liegt was? Dieselben Lagebeziehungen wie bei sdo_geom.relate, nur über den Index.
  • sdo_filter – nur der Primärfilter, der grobe Blick über den Index

Index anlegen

Der Spatial Index ist ein R-Baum. Das R steht für Rechteck (englisch rectangle): Jeder Knoten speichert das kleinste Rechteck, das alle Geometrien unter ihm umschließt. Erfunden hat ihn Antonin Guttman 1984 an der University of California in Berkeley. Aufgebaut ist er wie ein B-Baum, nur mit Rechtecken statt Werten.

Schritt 1: Metadaten eintragen

insert into user_sdo_geom_metadata (table_name, column_name, diminfo, srid)
  values (upper('baum'), upper('geo'),
          sdo_dim_array(
            sdo_dim_element('x', 600000, 700000, pa_geo.toleranz()),
            sdo_dim_element('y', 5400000, 5500000, pa_geo.toleranz())
          ),
          25832);
  • Die View user_sdo_geom_metadata beschreibt je Tabelle und Spalte, in welchem Bereich die Koordinaten liegen, mit welcher Toleranz gerechnet wird und in welchem Koordinatensystem.
  • Hier: x von 600 000 bis 700 000 m, y von 5 400 000 bis 5 500 000 m in ETRS89 / UTM Zone 32N – der Märchenwald liegt mittendrin.

Schritt 2: Index anlegen

create index ids1_baum on baum(geo) indextype is mdsys.spatial_index_v2;
  • mdsys.spatial_index_v2 baut den R-Baum aus umschließenden Rechtecken. Er ist der aktuelle Indextyp für Spatial und wird bei jedem insert, update und delete automatisch nachgeführt.
  • Die Operatoren wie sdo_within_distance, sdo_nn oder sdo_filter nutzen ihn.
Kapitel 8 · Witterung und Knöchlein

Jeden Morgen ruft die Hexe: „Hänsel, streck deinen Finger heraus!“ Hänsel streckt ihr ein Knöchlein hin, und die Alte mit ihren trüben Augen merkt es nicht.

Das Knöchlein: Primär- und Sekundärfilter

  1. Index: Er fasst benachbarte Bäume in umschließende Rechtecke zusammen, die Knoten, und diese wieder in größere bis zur Wurzel.
  2. Primärfilter: Der Index vergleicht nur Rechtecke: Welcher Knoten berührt den Suchbereich? Nur der orangefarbene. Seine sechs Bäume sind die Kandidaten, die anderen Knoten liest die Datenbank gar nicht. Das ist so grob, wie die Hexe tastet: Unter den Kandidaten sind auch Knöchlein.
  3. Sekundärfilter: Nur für die sechs Kandidaten rechnet Oracle genau nach, ob sie im Suchbereich liegen. Zwei sind echte Treffer (rot), die vier Knöchlein (grau) fliegen raus.

Wie viele Bäume berühren die Lichtung?

select count(*)                                   -- nur Primärfilter
  from baum b
  cross join flaeche l
  where l.name = 'Lichtung'
    and sdo_filter(b.geo, l.geo) = 'TRUE';

select count(*)                                   -- Primär- und Sekundärfilter
  from baum b
  cross join flaeche l
  where l.name = 'Lichtung'
    and sdo_anyinteract(b.geo, l.geo) = 'TRUE';

Die Differenz sind die Knöchlein: Bäume im umschließenden Rechteck, die die Lichtung nicht berühren. Auf der Lichtung selbst wachsen keine Bäume; ein exakter Treffer steht genau auf ihrem Rand.

Lichtung umschließendes Rechteck der Lichtung Knöchlein: im Rechteck, berühren die Lichtung nicht Treffer: auf dem Rand der Lichtung

  • sdo_filter macht nur den Primärfilter: Er vergleicht über den Spatial Index die umschließenden Rechtecke, nicht die genaue Form der Lichtung.
  • Das Ergebnis ist eine Obermenge: Kein echter Treffer fehlt, aber die Knöchlein im Rechteck kommen dazu. Ohne Spatial Index geht es nicht.
  • Gut für eine schnelle grobe Vorauswahl, etwa alle Objekte in einem Kartenausschnitt.

100 000 Bäume: Welche stehen im Umkreis von 50 m ums Hexenhaus?

-- Funktion: läuft für jede Zeile
select count(*) as baeume
  from baum b
  cross join ort h
  where h.name = 'Hexenhaus'
    and sdo_geom.sdo_distance(b.geo, h.geo, pa_geo.toleranz()) <= 50;

-- Operator: fragt zuerst den Spatial Index
select count(*) as baeume
  from baum b
  cross join ort h
  where h.name = 'Hexenhaus'
    and sdo_within_distance(b.geo, h.geo, 'distance=50') = 'TRUE';

Epilog · … dann querien sie noch heute

Die Kinder schütten Perlen und Edelsteine aus ihren Taschen, und alle Sorge hat ein Ende.

Die Perlen zum Mitnehmen

  1. Spatial ist schon da: in jeder Oracle-Datenbank, ohne Zusatzlizenz.
  2. Ein Datentyp für alles: SDO_GEOMETRY, rein und raus mit WKT und GeoJSON.
  3. Immer eine SRID setzen – und x = Länge, y = Breite.
  4. Die Toleranz an einer Stelle; ohne SRID gilt sie in den Einheiten der Koordinaten.
  5. Linien dürfen sich kreuzen, Flächen nicht: prüfen und reparieren.
  6. Löcher zählen nicht: Die Lichtung gehört nicht zum Wald.
  7. Ohne Index tastet die Hexe jeden Finger ab.

Das Versprechen

-- Wie weit ist es?
sdo_geom.sdo_distance(a.geo, b.geo, pa_geo.toleranz())
-- Was ist in der Nähe?
sdo_nn(r.geo, k.geo, 'sdo_batch_size=10', 1) = 'TRUE'
-- Was liegt im Gebiet?
sdo_relate(l.geo, g.geo, 'mask=inside') = 'TRUE'

Und wenn sie nicht gestorben sind, dann querien sie noch heute.
